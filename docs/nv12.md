# Native NV12 support

Requirement: transport NV12 through FrameLink and its GStreamer source/sink,
with applicable unit and integration tests. This does not change the camera demo
or add a Vulkan RGB-to-YUV renderer.

## Scope

- Linux: GBM NV12 allocation, two-plane DMA-BUF descriptor transfer, CPU mapping,
  and GStreamer source/sink. Driver support for NV12 allocation is required.
- Windows and Android: NV12 remains unsupported; no support is implied by the enum.
- Wire protocol is version 4. Rebuild both peers; older versions are refused.
- CPU mapping requires linear buffers (`FL_MAP_CPU`). Nonlinear modifiers are
  refused rather than interpreted as linear memory.
- NV12 dimensions must be positive, even, and at most 8192 in either direction.
- No color-space conversion, colorimetry transport, GPU rendering/import
  qualification, or frame-rate improvement is claimed by these tests.

## C API

Create a Linux channel with `FL_FORMAT_NV12` and `FL_MAP_CPU`. Acquire a buffer
as usual, then call `flImageMapPlanes(image, &mapped)` from
`framelink_dmabuf.h`. `mapped.plane[0]` is Y (width bytes by height rows);
`mapped.plane[1]` is interleaved UV (width bytes by height/2 rows).
Use each plane's `pixels`, `stride`, `rowBytes`, and `rows`, never width*height
as an assumed UV offset. Call `flImageUnmap` before submission/release.
The legacy single-pointer `flImageMap` rejects NV12. DMA-BUF descriptors remain
available through `flImageDmabuf`, including per-plane FDs, offsets and strides.
CPU mapping brackets access with DMA-BUF cache synchronization; it does not
add GPU fences. Producers must finish external GPU work before submitting.

The consumer owns the format. Geometry requests cannot change RGB to NV12;
query the resulting geometry after requesting it. Resize while a consumer holds
a frame is declined without invalidating that frame or resetting slot ownership.

## Verification on Melchior

Build and run:

```sh
cmake -S . -B build -DFRAMELINK_BUILD_TESTS=ON -DFRAMELINK_BUILD_GST=ON
cmake --build build -j8
ctest --test-dir build --output-on-failure
```

Tests requiring real buffers need an accessible DRM render node and a GBM driver
supporting linear NV12. GStreamer integration also requires gstreamer-app headers.

- `roundtrip`: existing RGB cross-process regression.
- `nv12_layout`: even/odd/zero/oversized geometry, padded layouts, offsets,
  short pitches, bounds and arithmetic overflow.
- `nv12_roundtrip`: real two-process DMA-BUF transport, both planes verified
  byte-for-byte, eight-slot FD transfer, resize, held-frame resize refusal,
  producer reconnect, legacy map rejection and invalid geometry.
- `gst_nv12_roundtrip`: source/sink roundtrip with deliberately different plane
  strides and nonzero offsets in GstVideoMeta; every active Y/UV byte checked;
  NV12-to-RGB mismatch must report negotiation failure and deliver no frame.

These are correctness tests, not a throughput benchmark. GStreamer currently
copies CPU memory in both directions; NV12 support does not remove these copies.
