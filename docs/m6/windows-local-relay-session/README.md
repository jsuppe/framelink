# Explicit local relay session composition prerequisite

`fl_gst_session_open_local_native_relay` is an additive Windows C API for the producer side of an explicit local relay hop. The receiver uses existing `open_local_native`; FAR4 discovery and authenticated wire formats are unchanged. The upstream receiver must have a live, valid A/V config and identity running-time mapping. The exact upstream media, clock ID, generation, epoch and track IDs are propagated; session identity/credentials and queue budgets are independent. Capability fallback is forbidden. Upstream config/mapping are checked again before returning success. Callers hold/serialize sessions throughout setup; failure clears channel/policy outputs and cancels only the downstream session. Same-object aliasing rejects without cancelling upstream.

This creates an **independent pool**, not a same-allocation graft. It does not authorize foreign native buffer submission, implement automatic bin relaying, add asynchronous supervision or reconnect, or claim zero-copy across those independent pools. Existing pool-identity rejection stays mandatory. The next composition seam is authenticated same-allocation transfer/ownership binding for the downstream pool; the current consumer-owned local factory cannot silently adopt a producer's upstream allocation.
